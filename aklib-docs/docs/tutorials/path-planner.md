# The AKLib Planner

:::tip Open it now
**[▶ Launch the Path Planner](pathname:///planner/)** (also in the top navbar) — it opens in a new tab, runs entirely in your browser, and saves your work locally. Or open `AKLib/planner/aklib-planner.html` from the repo directly; both are the same tool.
:::

The planner is a visual auton editor built specifically for AKLib: you chain *different kinds of motions* — straight drives, turns, point moves, boomerangs, and pure-pursuit curves — on a field map, and it exports the exact C++ calls.

## The idea

An AKLib auton is a **sequence of typed segments**, and each segment's exit pose feeds the next segment. The planner models exactly that:

| Segment | Exports | Draw style |
|---|---|---|
| Drive | `chassis.driveDistance(d)` | straight line along heading |
| Turn | `chassis.turnToHeading(θ)` | rotation marker |
| Move to point | `chassis.moveToPoint(x, y)` | simulated arc |
| Boomerang | `chassis.moveToPose(x, y, θ)` | simulated curve |
| Pure pursuit | `Path::bezier(...)` + `chassis.follow(...)` | editable Bézier |
| Action / Comment | your C++, verbatim | ƒ badge at that spot |

The curves for point/boomerang segments are **approximate previews** (a simulated seek controller) — real robot arcs depend on your tune — but they're close enough to plan clearances.

**Field renders:** the canvas shows the official top-down field image, and the **Match / Skills** toggle in the header switches between the head-to-head and skills setups (your choice is saved with the route). The images live next to the planner as `field-match.png` / `field-skills.png` — replace them with next season's renders and everything keeps working. If they're missing, the planner falls back to a plain tile grid.

**Robot heading:** the robot square at the start pose has a bold front edge and a filled arrow poking out of its front; turn markers, boomerang targets, and the end of the route each get an arrow showing exactly where the robot's front points at that moment.

**Actions & comments:** the **+ Action / Comment** segment drops a ƒ marker at the current point in the route and opens a code box in the Inspector. Whatever you type — `intake.move_voltage(12000);`, `pros::delay(300);`, `// clamp here` — is emitted *verbatim, in sequence* between the motion calls around it. Actions don't move the robot; they're how you script intaking, scoring, and waits right where they happen.

**Simulate playback:** the **▶ Simulate** button animates a ghost robot along the whole predicted route in roughly real time, with a running clock and a total-time estimate shown right on the button. Move-to-point and boomerang segments replay the same seek simulation that draws their preview curves (including the settle-radius steering freeze near targets, like the real controller); turns rotate in place; actions pause for any `pros::delay(...)` they contain. Speeds assume a typical drivetrain scaled by each segment's `max speed`, so treat the clock as a planning estimate — good for spotting slow route sections and choreographing mechanism timing, not a stopwatch. Any edit stops playback automatically.

## Workflow

1. **Set the start pose** — click the *Start pose* row and type x/y/heading, or drag the robot square.
2. **Add segments** with the buttons (top-left). Each new segment spawns ahead of the previous end pose.
3. **Drag** endpoints on the field (0.5″ snap) or type exact numbers in the Inspector.
4. **Tune per-segment params** in the Inspector: max/min speed, early exit range (chaining!), timeout, reverse, `dlead`, lookahead.
5. For pure pursuit segments: drag the Bézier control points (small gray dots shape the curve); **+ Extend path** adds another curve to the same path.
6. **Copy** the generated C++ from the right panel into your auton.

The generated code emits parameters **only when they differ from defaults**, so simple routes stay readable:

```cpp
// ── Generated by AKLib Planner ──────────────────────────────
static aklib::Path route1_path1 = aklib::Path::bezier({
    {24, 48}, {36, 48}, {48, 60}, {60, 60},
}, {.maxSpeed = 0.9});

void route1() {
    chassis.setPose(24, 12, 90);
    chassis.driveDistance(24);
    chassis.turnToHeading(0);
    chassis.moveToPoint(48, 36, {.minSpeed = 0.35, .earlyExitRange = 6});
    chassis.follow(route1_path1, {.lookahead = 12});
}
```

## Saving routes

- **Autosave**: your work persists in the browser (localStorage) between sessions.
- **Export/Import JSON**: share `.aklib.json` route files with teammates or keep them in your repo next to the auton that uses them.

## Tips

- Heading convention matches AKLib: 0° = +x (right), counterclockwise positive, +y up.
- Chain segments visually: set `early exit range` ≈ 6 and `min speed` ≈ 0.3 on mid-route point moves and watch your auton stop pausing between motions.
- A drive segment dragged "behind" the robot goes negative — that's a back-up move, no reverse flag needed.
- Keep one planner tab per route; the route name box names the generated function.
